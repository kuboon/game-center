# tests

`-A` を要するテスト。 `deno task test` がワークスペースの `-P`
テストに続けて実行するので、通常は個別に起動しなくてよい。

`server/` 以下の単体テストと分けている理由は権限である。 サーバ本体は
`@libsql/client/web`(fetch ベース、ネイティブアドオンなし)で Turso
に接続するが、テストは同じ `Client` API をローカルの SQLite に対して動かしたい。
そのための `@libsql/client/node` はネイティブアドオンを読み込むため FFI
権限が要り、ワークスペース既定の `-P` では動かない。

## カバー範囲

- `migrate.test.ts` — `deno task db` と同じ CLI
  をサブプロセスで叩き、マイグレーションの適用・冪等性・`down.sql`
  によるロールバック、 スキーマの制約(外部キー、実績キーの一意性、解除経路の
  CHECK、二重解除)を検証する
- `users.test.ts` — `upsertUser` の初回作成・再サインイン・表示名の保持
- `support/db.ts` — 使い捨て DB を用意する共通ヘルパ

一時ディレクトリ内のファイル DB を使う。 `:memory:` を使わないのは、CLI
とクライアントが別プロセス・別コネクションであり、`:memory:`
だとデータベースを共有できないためである。
